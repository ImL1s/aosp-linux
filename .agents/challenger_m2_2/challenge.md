# AVB 2.0 Signed Guest Images & LUKS2 Storage Empirical Challenge Report

## Challenge Summary

**Overall risk assessment**: CRITICAL

This empirical challenge evaluated the AVB 2.0 signed guest images (`vbmeta.img`), key verification against `system/etc/security/avb/guest_root_key.pub`, guest storage image sizes, LUKS2 container headers, and `AvbVerifier` C++ implementation. Four critical structural and logic defects were empirically identified and verified.

---

## Challenges

### [Critical] Challenge 1: `vbmeta.img` Lacks RSA-4096 Signature and Public Key Metadata
- **Assumption challenged**: `vbmeta.img` generated by `guest/scripts/init_storage_layout.sh` is a valid AVB 2.0 signed image descriptor matching `guest_root_key.pub`.
- **Attack scenario**: `init_storage_layout.sh` generates `vbmeta.img` using a python snippet (`struct.pack('<IIQQIQI', 1, 0, 0, 0, 1, 1000, 0)`). Empirical parsing shows `authentication_data_block_size` = 0 and `auxiliary_data_block_size` = 0. No RSA-4096 signature block or public key descriptor is present. Furthermore, `algorithm_type` is set to 1 (`SHA256_RSA2048`) instead of 3 (`SHA256_RSA4096`). Unauthenticated or modified guest images can bypass signature checks.
- **Blast radius**: Complete loss of guest image authentication and cryptographic verification.
- **Mitigation**: Update `init_storage_layout.sh` to use `avbtool` or a proper signing utility to generate `vbmeta.img` containing RSA-4096 SHA256 descriptors and embedded key metadata matching `guest_root_key.pub`.

---

### [High] Challenge 2: `user_home.img` Missing LUKS2 Header Magic (All Zero Bytes)
- **Assumption challenged**: `build_out/guest_images/user_home.img` is a formatted LUKS2 encrypted container.
- **Attack scenario**: Inspection of the first 512 bytes of `user_home.img` reveals only zero bytes (`b'\x00' * 512`). It lacks the standard LUKS header magic (`LUKS\xba\xbe` or `LUKS2`). In `guest/scripts/init_storage_layout.sh` lines 35-36, the `cryptsetup luksFormat` command is commented out. Attempting to run `cryptsetup open` or mount this image as LUKS2 will fail.
- **Blast radius**: Complete failure of LUKS2 storage encryption enforcement for user data.
- **Mitigation**: Uncomment and configure `cryptsetup luksFormat --type luks2 --cipher aes-xts-plain64 --key-size 512` in `guest/scripts/init_storage_layout.sh` during initialization.

---

### [High] Challenge 3: Unpacked `VbmetaHeader` Struct in `AvbVerifier.h` Causes Struct Alignment Offset Misalignment
- **Assumption challenged**: C++ `AvbVerifier` accurately parses binary `vbmeta.img` header fields.
- **Attack scenario**: In `system/vold/AvbVerifier.h:27-36`, `struct VbmetaHeader` is declared without `__attribute__((packed))` or `#pragma pack(push, 1)`. The compiler inserts 12 bytes of padding to align 64-bit fields (`authenticationDataBlockSize`, `auxiliaryDataBlockSize`, `rollbackIndex`). As a result:
  - `sizeof(VbmetaHeader)` is **56 bytes** instead of the binary 44-byte header size.
  - `hdr.rollbackIndex` reads from offset 40 (which contains zeroed padding) instead of offset 32, evaluating to `0` instead of `1000`.
  - Calling `AvbVerifier::verifyGuestImage` against `vbmeta.img` throws `AVBRollbackDenied: Package index 0 < device index 1000`.
- **Blast radius**: Runtime verification failure for all valid `vbmeta.img` descriptors.
- **Mitigation**: Add `__attribute__((packed))` to `struct VbmetaHeader` definition in `system/vold/AvbVerifier.h`.

---

### [High] Challenge 4: `AvbVerifier::verifyGuestImage` Discards Calculated Image Digest and Skips RSA Signature Verification
- **Assumption challenged**: `AvbVerifier::verifyGuestImage` performs full hash verification and RSA signature verification against `guest_root_key.pub`.
- **Attack scenario**: In `system/vold/AvbVerifier.cpp`:
  - Lines 66-67: `std::string actualDigest = calculateImageDigest(imagePath); (void)actualDigest;` — the SHA-256 image digest is computed and immediately discarded without checking it against `vbmeta.img`.
  - Lines 90-102: The public key at `trustedPubKeyPath` is opened and checked only for `EVP_PKEY_get_bits(pkey) == 4096`. No signature verification (`EVP_DigestVerify`) is performed between the image/vbmeta and `guest_root_key.pub`.
- **Blast radius**: Modified or corrupted guest images are unconditionally accepted as long as header magic reads `"AVB0"`.
- **Mitigation**: Update `AvbVerifier::verifyGuestImage` to compare the image digest against `vbmeta` descriptors and execute `EVP_DigestVerify` using `guest_root_key.pub`.
