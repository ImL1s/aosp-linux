## 2. Adversarial Challenge Dimensions & Empirical Results

### Challenge Dimension 1: AF_VSOCK Socket Connect & Error Handling
- **Hypothesis**: Does `VsockTerminalClient.connect(...)` issue a genuine `Os.connect(mSocketFd, address)` call against Guest CID (port 5001), and does it cleanly handle invalid CID, closed port, or connection refusal?
- **Empirical Test**: Executed `VsockTerminalClientEmpiricalTest` with invalid CIDs (`CID 9999`) and un-bound vsock addresses.
- **Result**:
  - `Os.connect(mSocketFd, address)` is invoked with `VmSocketAddress(5001, guestCid)`.
  - On connection refusal or unavailable vsock driver, an `IOException` containing diagnostic context (`"Failed to connect AF_VSOCK socket to CID..."`) is thrown.
  - **PASS**

### Challenge Dimension 2: Socket Descriptor Leak Safety
- **Hypothesis**: Could failed socket connection attempts leak open file descriptors (`mSocketFd`), causing process file descriptor exhaustion over time?
- **Empirical Test**: Executed `VsockTerminalClientEmpiricalTest` running 100 consecutive failed connection attempts to non-existent CIDs while inspecting `/dev/fd`.
- **Result**:
  - Initial open FDs: 9
  - Final open FDs after 100 failed connections: 9
  - Net FD Delta: **0**
  - Confirmed: `close()` in the `catch` block reliably closes `mSocketFd` and nullifies references. Zero descriptor leaks.
  - **PASS**

### Challenge Dimension 3: Session ID Formatting & Dynamic Service Integration
- **Hypothesis**: Does `LinuxManagerService` issue 16-byte session IDs that satisfy `VsockPtyFramer`'s strict `SESSION_ID_SIZE = 16` assertion, and does `TerminalView` query `ILinuxManager.createTerminalSession`?
- **Empirical Test**: Checked generated string format (`"session_%08d"` -> 16 bytes, e.g. `"session_00001001"`) and validated framing assertion checks against null, 12-byte, 20-byte, and 16-byte session IDs.
- **Result**:
  - Session IDs shorter or longer than 16 bytes immediately throw `IllegalArgumentException`.
  - 16-byte session IDs generated by `LinuxManagerService` pass framing validation cleanly.
  - **PASS**

### Challenge Dimension 4: Read Thread Teardown & Resource Cleanup
- **Hypothesis**: Does `VsockTerminalClient.close()` properly interrupt `VsockReadThread` and close background input/output streams?
- **Empirical Test**: Instantiated loopback server, connected client socket, verified active `VsockReadThread`, invoked `client.close()`, and monitored thread state post-close.
- **Result**:
  - `VsockReadThread` terminated cleanly within 150ms after `close()`.
  - Streams closed without hanging or leaking threads.
  - **PASS**
